## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | X-API-Key header crosses this boundary; untrusted input |
| API→DB | SQL via SQLAlchemy parameterized queries; no raw string formatting |
| Docker volume | Named volume `db_data` at `/app/data`; not bind-mounted to host `/` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Elevation of Privilege | `verify_api_key` in `app/core/auth.py` | mitigate | `secrets.compare_digest(api_key, expected)` — constant-time comparison; `api_key is None` check before compare_digest to avoid TypeError |
| T-1-02 | Information Disclosure | `app/core/auth.py` + `app/core/logging.py` | mitigate | `api_key` value NEVER passed to structlog; `SecretStr` type on settings field prevents repr/str exposure; CorrelationIdMiddleware logs path/method/correlation_id only |
| T-1-03 | Information Disclosure | SQLite file + Docker volume | mitigate | DB file at `/app/data/` (not web root); docker-compose uses named volume `db_data`, not bind mount; DB file not in `COPY . .` build context (`.dockerignore` should exclude `*.db`) |
| T-1-04 | Tampering | `execute_url` / `compensate_url` step fields | mitigate | Pydantic `HttpUrl` type validates URL format at definition create time (Plan 03); Phase 1 schema definition enforces this contract |
| T-1-SC | Tampering | pip install in Dockerfile | mitigate | All packages [OK] per slopcheck audit; pinned versions in pyproject.toml prevent version drift; no `--upgrade` in pip install |
</threat_model>
