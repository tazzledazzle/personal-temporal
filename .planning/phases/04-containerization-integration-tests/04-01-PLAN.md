  <files>Dockerfile</files>
  <read_first>
    Read the full Dockerfile and pyproject.toml before editing.
    - Dockerfile: verify python:3.11-slim base, WORKDIR /app, pip install ".[dev]",
      COPY . ., RUN mkdir -p /app/data, EXPOSE 8000, CMD with uvicorn --workers 1
    - pyproject.toml: confirm the package name and entry point (app.main:app)
  </read_first>
  <action>
    Read Dockerfile and pyproject.toml. Verify the following exact constraints are met.
    If any constraint is violated, fix it:

    1. Base image is exactly `python:3.11-slim` (not `python:3.12`, not `full`, not `alpine`).
    2. `WORKDIR /app` is set before any COPY or RUN commands.
    3. `COPY pyproject.toml .` then `RUN pip install --no-cache-dir ".[dev]"` — dep layer before
       app code copy, for Docker layer caching.
    4. `COPY . .` follows the pip install step.
    5. `RUN mkdir -p /app/data` creates the SQLite data directory.
    6. `EXPOSE 8000` is present.
    7. CMD is exactly:
       `CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "1"]`
       The `--workers 1` flag MUST be a literal string in the CMD array, not an env var reference.
       Add a comment above CMD: `# MANDATORY: --workers 1 — SQLite single-writer constraint.`

    After verification/fix, run:
      docker build -t workflow-executor-test .

    If the build fails, read the error output and fix the Dockerfile. Common issues:
    - Missing setuptools in build system → already in pyproject.toml, should work
    - aiosqlite C extension → python:3.11-slim has gcc; if needed add `RUN apt-get update && apt-get install -y --no-install-recommends gcc && rm -rf /var/lib/apt/lists/*` before pip install
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host → container | docker-compose passes API_KEY and DATABASE_URL as env vars to the container |
| container → SQLite file | The container writes to /app/data/workflows.db via named volume |
| network → container | Port 8000 is exposed; no TLS at the Docker layer (single-node dev) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | docker-compose.yml API_KEY default | accept | Default `change-me-in-production` is not a real secret; documented as placeholder; operator must override |
| T-04-02 | Tampering | SQLite volume — container runs as root | mitigate | Dockerfile does not drop privileges by default; for interview scope this is accepted; note for production: add `USER appuser` with `RUN useradd -m appuser && chown -R appuser /app/data` |
| T-04-03 | Denial of Service | --workers 1 constraint | accept | Intentional single-worker design for SQLite; multiple workers cause file-lock corruption; constraint is documented in CMD comment |
| T-04-SC | Tampering | pip install ".[dev]" installs packages | mitigate | All packages are from pyproject.toml which was audited in Phase 1; no new packages added in this plan; slopcheck not required for no-new-install plans |
</threat_model>
